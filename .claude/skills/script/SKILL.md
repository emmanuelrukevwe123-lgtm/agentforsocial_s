# /script

Video: `$ARGUMENTS`. If empty, run `python scripts/db.py video-list` and ask which one.

## Facts I can claim
!`python -m common.profile --summary`

## Do this
1. Run `python scripts/db.py video-show $ARGUMENTS` and read `media/$ARGUMENTS/script.md`
   (template, or a previous draft to revise). If the video has an idea, `python scripts/db.py idea-show <idea_id>`.
2. Write the script into `media/$ARGUMENTS/script.md`, keeping the front matter:
   - `## Script`: numbered lines `[1] ...`, one short spoken sentence each (max ~15 words).
     Line 1 is the hook. The last line is the call to action (repo or portfolio).
     Length: `target_seconds` x 2.5 words, within 10%.
   - `## Visuals`: same numbers, one idea per line for the paper-cut animation (which icon, word or photo
     appears, and on which word). Visuals are generated by `/scenes`; I do not film.
   - `## Sources`: a URL for every fact that is not about my own work (official docs first).
   - `## Alt hooks`: two other hook options, one line each.
   - Plain spoken English. No markdown inside lines. Write numbers as I would say them.
3. Use the `fact-checker` subagent on `media/$ARGUMENTS/script.md`. Pass it the "Facts I can claim" block above.
4. Fix every WRONG item. Keep UNSURE items only if I can confirm them; otherwise cut or soften them.
5. Save: `python scripts/db.py script-save $ARGUMENTS --fact-check pass` if nothing unresolved,
   else `--fact-check issues --notes "<short list>"`.
6. Show me the script lines, the estimated seconds, and any open issues. Nothing else. Ask: approve or change?
7. On changes: edit, re-save, and re-run the fact-checker only if a factual claim changed.
   On approval: `python scripts/db.py script-approve $ARGUMENTS`.
   Then tell me: record the voiceover (any file with "voice" in its name, e.g. `voice.wav` or `Voice Over.mp4`)
   into `media/$ARGUMENTS/`, reading line by line with a short pause between lines. Next steps: captions, `/scenes`.
